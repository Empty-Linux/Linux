BUG-DRV-001: Баланс не обновляется после завершения заказа

Информация

| Поле | Значение |
|------|----------|
| ID | BUG-DRV-001 |
| Дата обнаружения | 17 октября 2025 |
| Severity | High |
| Priority | P1 |
| Статус | Fixed |
| Эндпоинт | GET /balance |

Описание

После завершения заказа баланс водителя не обновляется автоматически. Требуется повторный запрос через несколько минут.

Шаги воспроизведения

1. Водитель завершает заказ (status: completed)
2. Сразу запросить баланс GET /balance
3. Баланс не изменился
4. Подождать 2-3 минуты
5. Запросить баланс снова
6. Баланс обновился

Ожидаемый результат

Баланс должен обновляться сразу после завершения заказа (или в течение нескольких секунд).

Фактический результат

Баланс обновляется с задержкой 2-3 минуты.

Причина

Kafka consumer обрабатывает событие order.completed с задержкой из-за большого batch size.

Исправление

| Дата | Действие |
|------|----------|
| 18 октября 2025 | Уменьшен batch size для consumer |
| 19 октября 2025 | Верификация - задержка менее 5 секунд |

BUG-DRV-002: Водитель может принять заказ будучи офлайн

Информация

| Поле | Значение |
|------|----------|
| ID | BUG-DRV-002 |
| Дата обнаружения | 18 октября 2025 |
| Severity | Medium |
| Priority | P2 |
| Статус | Fixed |
| Эндпоинт | POST /orders/{id}/accept |

Описание

При определенных условиях водитель может принять заказ, находясь в статусе offline.

Шаги воспроизведения

1. Водитель переходит в онлайн
2. Получает предложение о заказе
3. Переходит в офлайн
4. Быстро отправляет accept на полученный заказ
5. Заказ принимается, хотя водитель офлайн

Ожидаемый результат

Status Code: 403 Forbidden с сообщением "Driver must be online to accept orders"

Фактический результат

Status Code: 200 OK, заказ принят

Причина

Проверка статуса водителя происходит после проверки существования заказа, что создает race condition.

Исправление

| Дата | Действие |
|------|----------|
| 19 октября 2025 | Добавлена проверка статуса водителя в начало |
| 20 октября 2025 | Верификация - корректно возвращает 403 |

BUG-DRV-003: Отсутствует валидация размера загружаемого документа

Информация

| Поле | Значение |
|------|----------|
| ID | BUG-DRV-003 |
| Дата обнаружения | 18 октября 2025 |
| Severity | Medium |
| Priority | P2 |
| Статус | Fixed |
| Эндпоинт | POST /documents |

Описание

Можно загрузить файл размером более 10MB, что приводит к ошибке на стороне хранилища.

Шаги воспроизведения

1. Подготовить файл размером 15MB
2. Отправить POST /documents с этим файлом
3. Запрос принимается
4. Через несколько секунд возвращается 500 ошибка от storage

Ожидаемый результат

Status Code: 400 Bad Request с сообщением "File size exceeds maximum limit (5MB)"

Фактический результат

Запрос принимается, затем 500 Internal Server Error

Исправление

| Дата | Действие |
|------|----------|
| 19 октября 2025 | Добавлена валидация размера файла на уровне API |
| 20 октября 2025 | Верификация - корректно возвращает 400 |

BUG-DRV-004: Рейтинг отображается как null для нового водителя

Информация

| Поле | Значение |
|------|----------|
| ID | BUG-DRV-004 |
| Дата обнаружения | 20 октября 2025 |
| Severity | Low |
| Priority | P3 |
| Статус | Fixed |
| Эндпоинт | GET /profile |

Описание

Для водителя без завершенных заказов поле rating возвращается как null вместо дефолтного значения.

Шаги воспроизведения

1. Создать нового водителя
2. Запросить профиль GET /profile
3. Поле rating = null

Ожидаемый результат

rating: 5.0 (или другое дефолтное значение) для нового водителя

Фактический результат

rating: null

Влияние

- Может вызвать ошибку на клиенте при отображении рейтинга
- Некорректное отображение в UI

Исправление

| Дата | Действение |
|------|----------|
| 20 октября 2025 | Добавлено дефолтное значение rating: 5.0 |
| 21 октября 2025 | Верификация - корректно возвращает 5.0 |
